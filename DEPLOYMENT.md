# Deployment Guide

This guide covers deploying the Second Brain API to Railway.app with PostgreSQL.

## Prerequisites

- Railway.app account
- GitHub repository connected to Railway (optional but recommended)
- PostgreSQL database (Railway provides this)

## Railway Deployment Steps

### 1. Create a New Project on Railway

1. Go to [Railway.app](https://railway.app)
2. Click "New Project"
3. Select "Deploy from GitHub repo" (or "Empty Project")
4. Select your repository

### 2. Add PostgreSQL Database

1. In your Railway project, click "New Service"
2. Select "Database" → "PostgreSQL"
3. Railway will automatically create a Postgres instance
4. Copy the `DATABASE_URL` connection string

### 3. Configure Environment Variables

In your Railway project settings, add the following environment variables:

```bash
# Database (auto-generated by Railway Postgres service)
DATABASE_URL=postgresql://user:password@host:5432/database_name

# Authentication
API_AUTH_TOKEN=your-secret-token-here

# API Keys
ANTHROPIC_API_KEY=your-anthropic-api-key

# CORS (set to your frontend domain)
CORS_ORIGIN=https://yourdomain.com

# Server Configuration (optional, defaults provided)
NODE_ENV=production
PORT=3001
HOST=0.0.0.0
LOG_LEVEL=info
```

### 4. Deploy

Railway will automatically deploy when you push to your connected GitHub repository.

Or manually deploy:
```bash
railway up
```

### 5. Run Database Migrations

After the first deployment, you'll need to run migrations:

```bash
# Connect to your Railway service
railway run pnpm --filter @second-brain/api db:generate
railway run pnpm --filter @second-brain/api db:migrate
```

Or use Railway's shell:
1. Go to your service in Railway dashboard
2. Click on "Shell" tab
3. Run:
   ```bash
   cd packages/api
   pnpm db:generate
   pnpm db:migrate
   ```

## Alternative: Fly.io Deployment

### 1. Install Fly CLI

```bash
curl -L https://fly.io/install.sh | sh
```

### 2. Login to Fly

```bash
fly auth login
```

### 3. Create a Fly App

```bash
fly launch --no-deploy
```

### 4. Add PostgreSQL

```bash
fly postgres create
fly postgres attach <postgres-app-name>
```

### 5. Set Environment Variables

```bash
fly secrets set API_AUTH_TOKEN=your-secret-token
fly secrets set ANTHROPIC_API_KEY=your-api-key
fly secrets set CORS_ORIGIN=https://yourdomain.com
```

### 6. Deploy

```bash
fly deploy
```

## SSL/HTTPS

Both Railway and Fly.io automatically provide SSL/HTTPS certificates for your deployed application. No additional configuration needed.

## Health Checks

The API includes a health check endpoint at `/health` that returns:
- API status
- Database connectivity
- LLM provider status

Railway and Fly.io will automatically use this endpoint for health checks.

## Monitoring

- **Railway**: Built-in logs and metrics in the dashboard
- **Fly.io**: Use `fly logs` and `fly status` commands

## Database Migrations

When you update the schema, generate and run migrations:

```bash
# Locally
pnpm --filter @second-brain/api db:generate

# On Railway
railway run pnpm --filter @second-brain/api db:generate
railway run pnpm --filter @second-brain/api db:migrate

# On Fly.io
fly ssh console -C "cd packages/api && pnpm db:generate && pnpm db:migrate"
```

## Troubleshooting

### Connection Issues

If you can't connect to the API:
1. Check that environment variables are set correctly
2. Verify DATABASE_URL is correct
3. Check logs for errors: `railway logs` or `fly logs`

### Database Migration Errors

If migrations fail:
1. Check DATABASE_URL is accessible
2. Ensure Postgres is running
3. Check migration files in `packages/api/src/db/migrations`

### Authentication Issues

If getting 401 errors:
1. Verify API_AUTH_TOKEN is set
2. Check your client is sending the correct Bearer token
3. Confirm the token matches between client and server
